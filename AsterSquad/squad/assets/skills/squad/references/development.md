# 开发、集成与排错

## 接口边界

Fleet 注册表与代理在 `squad/fleet.py`；成员状态、授权和生命周期在 `service.py`/`store.py`；认证 MCP 在 `mcpserver.py`；worker 在 `worker.py`；skill 来源和内置同步在 `skills.py`。通过公开 Harness SDK 创建/恢复 Thread，通过 Relay 公开接口创建域内账号，不访问二者的私有 Session 或存储来伪造状态。

多空间工作台入口是 `aster-console` / `python -m squad.fleet`；单空间服务是 `aster-squad` / `python -m squad`。数据与源码分离，默认 `~/.aster-squad/`，支持 `ASTER_SQUAD_HOME` 和 `--root`。真实模型由宿主配置模型目录与凭据；fake 是明确标记的离线演示，不代表真实模型推理能力。

## 排错路径

| 现象 | 先核对 |
|---|---|
| 创建或配置失败 | handle、容量、模型 allowlist、路径校验、parent 授权和实际错误 |
| 工作台显示 online，成员没有回复 | 模型错误、worker 日志、已有事件、监听状态、Relay 队列，逐层定位 |
| 收到通知却没读到消息 | Relay 身份/域、原始待收队列、是否已有其他消费者确认；读 Relay 指南 |
| 网页能登录但 MCP 401/403 | 浏览器 session 和机器 token 是独立凭据；核对账号是否停用/撤销 |
| 修改来源后目录未变化 | 文本更新在下一 Step 扫描；新来源清单和沙箱掩码需重新启动成员 |
| 恢复报错 | 保留原 Thread，检查原错误、checkpoint、写锁和当前配置，必要时由宿主显式 recover |

不输出 token、providers.env 或整份含历史的 API 请求。日志取必要的错误码、时间和上下文，使用稳定 ID 关联，不用新建成员掩盖失败。

## 验证

优先用临时数据、脚本模型、真实 MCP/SDK 和沙箱检查完整链路：创建成员 → 事件 → 工具调用 → 消息回执 → 原 Thread 暂停/恢复。文档更新验证包内引用和实际目录；网页变更验证浏览器、API、存储与返回结果。真实模型检查应控制次数和范围，自动化小屏不等于真实手机硬件验证。

## 当前实现范围

工作台按需创建 Squad，不设固定 8 个空间上限，每个最多 16 个成员；成员归档不复用 slot，删除空间保留本机数据，新空间不复用已有目录。默认 Relay 支持私聊和群聊，但跨空间自动账号共享、附件、通用模块市场、费用预算和任意故障自动重试不能视为已提供。正常暂停超时时保留进程与登记，不自动强制结束，不承诺任意崩溃下恰好一次执行、网络隔离或恶意宿主防护。
