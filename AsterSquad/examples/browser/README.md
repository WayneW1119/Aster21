# Playwright browser for Squad

Install Node.js and `@playwright/mcp` in a dedicated tool directory. Install Chromium with `playwright install chromium`. Use the absolute paths to Node, the MCP entry point, and that Chromium executable in `mcp-services.json`. Merge the `browser` entry into the host-managed MCP catalog. A running Squad discovers new entries with `default: false`. Windows Studio preserves custom entries when it regenerates its built-in entries.

Register this directory as a skill source or install `aster-browser` in the selected member's skill directory. Select **Playwright browser** in the member's MCP settings. Each stdio connection opens a separate browser session with temporary browser state. The browser starts on first use and closes after five idle minutes; the next call opens a fresh session, so tabs and login state are not durable. The tool list exposes page interaction and screenshots. If a screenshot comes back as a file, use the Harness `view_image` tool to inspect it.

On Linux/WSL, Harness 0.1.27 supports nested user namespaces while preserving the member's filesystem mounts, PID isolation and syscall restrictions. Real stdio tests with Playwright MCP 0.0.85 verify page interaction, screenshots and Chromium's namespace/PID/network/seccomp sandboxes. Enable the member's existing **local IPC** permission: Chromium needs Unix sockets. This does not grant host services or write access to the host browser cache. Keep Node, the MCP package, Chromium and their system dependencies readable under the member's path policy.

Use `mcp-services.linux.json` on Linux, replacing its three `/path/to/...` placeholders. It sets `XDG_CACHE_HOME` and `XDG_CONFIG_HOME` under `/tmp`, which is private to each sandboxed execution with local IPC enabled. `--isolated` keeps browser state temporary; screenshots and explicit output files remain in the workspace. No browser dependency is added to Harness itself. The original catalog is a Windows path example.

Do not silently add `--no-sandbox`, disable the member sandbox, or grant root on launch failure. An independently operated authenticated HTTP browser MCP service remains an alternative; its filesystem and session isolation must be enforced by that service independently of member path grants.

On Windows, an ordinary user process can run the full browser example. Under MXC, direct launches reproduced the failure without Playwright or MCP. Full Chromium exited with `0xC0000022` (`STATUS_ACCESS_DENIED`) whether its own sandbox was enabled or disabled. Chromium Headless Shell exited with `0x80000003` when its sandbox was enabled. With that inner sandbox disabled and the outer MXC policy active, Headless Shell loaded a loopback test page, filled and submitted a form through MCP, and produced a PNG. A separate Node probe under the same filesystem rules could read the test workspace and received `EPERM` reading an ungranted sibling file. These probes cover controlled local pages. The inner Chromium sandbox supplies isolation between browser components and pages, so the test does not establish equivalent protection for browsing arbitrary sites. The sample catalog retains the browser sandbox.
