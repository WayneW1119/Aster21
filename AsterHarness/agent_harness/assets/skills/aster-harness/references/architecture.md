# 架构与机制

## 概念

| 概念 | 含义与生命周期 |
|---|---|
| Harness home | 模板、凭据及托管 Thread 的持久数据根；默认 `~/.aster/`，`ASTER_HOME` 可覆盖；已有 `~/.harness/` 在兼容条件下沿用 |
| Agent 配置/模板 | 创建时的模型、instruction、工具和运行配置来源；不持续覆盖已创建 Thread |
| Thread | 持久身份和经历，拥有稳定 Thread ID、历史、记忆、待处理事件及发生器注册 |
| Session | 某次创建或恢复后的运行实例；暂停后结束，下次恢复产生新的运行实例 |
| workspace | agent 普通文件操作的工作目录；与 Thread 的内部存储、私有记忆分开 |
| Step | 消费一批事件并推进模型/工具工作的调度单元；不是“用户说一句、助手答一句”的固定会话轮次 |

Python SDK 可显式指定 home 和 workspace。文件落点必须查看实际配置，不能仅由默认路径推断。

## 数据流

```text
终端输入 / 宿主 send、emit / 定时器 / 程序通知
                    ↓
               输入事件队列
                    ↓
     Session 调度 → 构造上下文 → 模型请求
                    ↑              ↓
         新输入和工具回执 ← 工具分发与执行
                    ↓
            继续工作或等待事件
```

队列通知、成功入队、模型看到事件、工具成功、业务任务完成是不同事实。模型等待时不需要重复调用自身；外部事件唤醒调度。常驻还依赖宿主保持进程运行、有效认证和事件来源，不是永不失败的承诺。

## 组件和上下文

SDK/CLI 负责配置和生命周期；Session 负责调度；模型客户端负责请求/响应；工具路由器执行本地工具、MCP 和其他已注册来源；沙箱约束普通文件与进程操作；历史存储负责持久记录、验证、恢复与 compact。

模型看到的上下文包含通用及运行规则、agent instruction、WorldState 固定基线和有效历史。WorldState 管理 memory、skills、tools、environment 等部分：基线固定，变化追加到历史；不会每步悄悄重写旧前缀。工具定义仍按原生工具协议提供，延迟工具需搜索发现。

compact 是保留必要摘要和精确状态检查点后重建有效上下文，不等于清除经历；完整读取的文档可能离开上下文，需要时重新读取。私有记忆通过专用工具更新，不靠修改历史来“记住”。

## 持久化边界

正常暂停保存待处理事件及来源注册，停止其管理的进程。恢复保留 Thread ID、记忆和历史；活跃程序来源从入口重启，并保留自己的状态目录。shell 进程句柄、Python 对象或临时 Code Mode 状态不保证恢复。

失败 Thread 的 `recover` 是宿主显式执行的校验和审计追加，不重放未完成工具，不补猜缺失记录。截断文件、缺失 checkpoint 或未配对的调用/回执仍可能拒绝恢复。命令用法见 `agent-configuration.md`，SDK 见 `sdk.md`。
