# 排错：先确认失败层

| 现象 | 核查方向 |
|---|---|
| 程序在线却不响应 | 是否有输入事件、发生器是否活跃、通知是否已入队；`online` 不等于模型或业务健康 |
| 事件有通知却缺业务内容 | 通知可能只是索引；按具体应用协议获取原始内容，不能推断通知等于已读取 |
| 模型错误、额度或认证错误 | 请求实际使用的模型、认证方式、服务商错误码和时间；不输出原始凭据或整份含历史的请求 |
| ChatGPT 身份时间校验失败 | 比对本机与服务端时间；运行时只容忍 5 秒偏差。暂存身份过期可用已保留的最新刷新凭据续换一次并重新严格验证；共享账户可能影响多个 Thread。不要删除凭据、跳过签名/时间校验或反复重启，先由宿主检查刷新状态 |
| 模型重试中 | 明确的临时过载、限流或传输失败会等待后重试同一请求；检查 model_retrying 的 attempt、max_retries 和 delay_seconds。每份请求最多重试 5 次且受 10 分钟预算约束；超出预算明确停止，由宿主处理，不自动循环重启。公钥获取失败可有限重试，身份校验、额度及未知错误仍需诊断，不要重复业务操作 |
| 找不到工具 | 检查来源配置与连接，再执行工具发现；工具定义可能在 compact 后需要重新搜索 |
| 切到 GPT 后 HTTP 400 | 区分请求格式拒绝与网络/额度错误。兼容服务留下的 `namespace::tool` 历史调用名在计划接口上需拆成 namespace 和 name；0.1.13 起仅在发送时投影，原历史、调用 ID 和失败回执保持不变，不重放工具操作 |
| 模型 HTTP 520 | 上游网关未能获得正常响应；0.1.14 起纳入同一有限退避机制，仍受 5 次重试和 10 分钟预算约束。不能据此认定本机 VPN 或模型额度异常；不扩大重试上限，不自动循环重启 |
| 找不到 skill 或读失败 | 检查目录诊断、名称冲突、resource 相对路径及当前权限；动态来源不绕过文件 deny |
| 命令或文件权限错误 | 对照 environment 区分 read、write、deny、路径不存在与沙箱探测失败，不自行关闭沙箱 |
| 恢复失败 | 核对 Thread ID、写入锁、历史完整性、checkpoint、当前配置及记忆一致性；交由宿主诊断原 Thread |

暂停和恢复属于宿主生命周期操作。`recover` 只在满足校验条件时追加审计，不能修复任意崩溃。不要手工重写 rollout、复制别人的记忆或新建同名 Thread 来制造“恢复成功”。

收集证据应包含版本、错误类别、有效配置的非秘密字段、预期与实际行为、已做的最小检查。验证 SDK 或发生器优先使用脚本客户端和有限自测；真实模型请求只在确有必要时进行。
