# 主动范围压缩：第一层实现

现已升级为按需目录快照编号和稳定 ID 双寻址，当前工具定义见
[history-navigation.md](history-navigation.md)。本文继续说明底层提交与恢复机制。

## 用法与定位

Agent 决定整理时机、选择范围并撰写摘要，Harness 校验并提交替换。不新增 Turn，不调用
独立摘要模型，也不使用服务端不透明 compaction item。这是我们的设计，不声称是 Codex 原生工具。
仍沿用 ContextManager 管历史、StepContext 捕获请求、Session 管提交、rollout 管持久化的职责划分。

典型流程：

1. 完成一阶段工作；必要时先更新记忆，再读取/检查工具回执。
2. 调用 `query_history_directory` 获取快照编号与 `view_id`，缺少证据时按需读取。
3. 选择连续、包含起止 ID 的范围，准备忠实的阶段交接摘要。
4. **单独**调用 `compact_history(view_id,start,end,summary)`；数字依据该目录快照解析为稳定 ID。
5. 普通工具回执作为事件入队；下一 Step 的请求使用替换后的有效历史。
6. 需要细节时，用 `query_compaction` 看来源结构，按路径/稳定 ID 读取或搜索原文。

不再给原生 item 插入数字，也不在每次请求尾部生成目录。目录是普通查询工具的结果，
按需进入历史；其自身调用和回执不在该快照内。文件整理、验证、记忆更新可以在查询前后
进行，普通追加不改变快照编号；新追加 item 若需纳入选区，应获取新目录。
成功回执包含 status、summary_id、compacted_at、目录 ID 和计数，提示旧目录过期，
下次压缩应重新获取目录。此规则通过提示引导，不对旧快照实行一律拒绝；
实际选区必须仍为相同的连续可见记录。旧目录清单细节可以在后续压缩中省略。
summary 长度为 1–16000 个 Unicode 字符，不能全为空白。没有自动 Token 收益保证。

## 两层历史与来源

归档不可变：旧输入、调用、回执、模型输出仍在；追加新摘要和可选记忆检查点。
有效历史只替换所选范围的引用，范围之外不隐式删除或改写。当前模型响应及回执正常继续记录。
摘要作为标准 user-role message，文本包在 `<history_summary>` 中，明确标注为工作数据、
非新用户请求或授权；不存在自定义的 Responses item 类型或额外 wire metadata 字段。

`revision` 是归档追加时钟，`generation` 是有效视图替换时钟。两者独立。
摘要带 `replaced_count`（直接来源条数）与 `leaf_count`（递归覆盖的原始条数，非 Tokens）。
来源保存为 ID 关系，不递归复制整棵树。再次压缩摘要后，旧摘要和它的来源仍可查询。

`query_compaction(target,offset,limit)` 返回计数和最多 50 个子摘要位置/ID，不列全部子项 ID;
范围读取支持直接来源或原始叶记录，不把归档重新塞回有效历史，整个 JSON 有字符预算。

## 安全边界

- 必须是当前响应中的唯一工具调用；需要文件/记忆操作时先做，再在后续 Step compact。
- 不能选择当前模型响应批次的任何 item。
- 起止必须存在于当前有效历史且顺序正确；快照选区内部已被替换则拒绝，不能误用旧编号。
- 不能截断 function_call / function_call_output 配对，也不能包含回执还没进入历史的调用。
- 返回 running handle 已完成调用协议；不必等待后台进程或定时器结束才能压缩其登记回执。
- 排队中的新用户消息和事件不在选区中，不被压缩；它们仍在之后的 Step 正常消费。
- 校验失败返回普通错误回执，历史不变；不自动扩大选区或替 Agent 猜摘要。

这是结构护栏，不验证摘要是否忠实，也不限制宿主文件权限。原始用户约束应由 Agent 忠实保留；
只保留摘要意味着模型可能遗忘被摘要漏掉的信息，这是主动摘要方案固有风险。

## 记忆的一致性

记忆保存长期职责、原则、可复用事实和持续工作状态；摘要保存特定工作阶段的交接信息。
无需每次压缩都写记忆，适量重复可以，避免两边都复制大段流水账。

index.md 基线独立于历史，不编号、不参与 compact；正常写入通过明确版本追加历史。
压缩最早的连续更新链可推进基线到选区结束时的准确版本，不是磁盘上可能更晚的版本。
若较早更新仍在选区外，则在摘要之后、替换范围原位置插入一个完整快照，不能放到历史尾部。
快照再次被压缩时按相同规则处理，多个中间版本收敛到最后所需版本。
整体历史压缩将基线推进到当前版本；旧于基线的调用只是操作记录，不应再次应用。
仅详情文件变化、失败且未改变 index.md、普通读取均不生成索引版本。
每次请求前验证独立基线 + 可见历史可重建准确 index.md；不一致停止。外部修改不静默吸收。
详见 [memory-projection.md](memory-projection.md)。

## 持久化与恢复

Session 先准备并验证操作，再 fsync **一条** `history_compacted` 记录，然后应用内存替换。
记录包括版本、generation、源 ID、摘要 ID/文本、计数、可选记忆检查点以及新记忆投影。
新操作 version=2 将检查点放在摘要之后；version=1 保持旧的尾部插入语义以兼容回放。
恢复逐条重放
response_item 和 history_compacted，校验分配 ID、来源、计数和代数，恢复有效引用及来源关系。
不会把 archive 全部重插入模型输入，不重执行工具。旧无 compact 的 Thread 继续兼容。
包含新记录的 Thread 不能用旧版程序恢复；格式仍是本地 rollout v1 的扩展记录，不是 Codex 格式。

磁盘写入失败导致 Session 失败，不能伪装成普通工具错误后继续；损坏或不完整日志拒绝恢复。
仍只支持正常关闭恢复，不新增任意崩溃点自动修复。压缩回执尚在队列时正常暂停也能恢复消费。
archive 查询游标跨压缩/恢复继续有效；effective 游标仅在 generation 没变时继续有效。
所有归档仍载入内存，压缩减少的是模型输入，不保证减少 Harness 内存或磁盘体积。

## 上下文预算提醒

运行时使用 Responses 服务端返回的 `usage.input_tokens`，默认从 100,000 tokens
开始发送 `context_budget_warning` 事件。同一有效历史 generation 内，以阈值的
四分之一为增长间隔提醒一次，跨越多个档位只发送一条。缓存输入也计入上下文，
不扣除 cached_tokens，不使用累计账单用量；缺少有效统计时不推测。

提醒在整个响应的工具批次执行完后入队，后续 Step 和其他事件一起消费。
统计指向刚完成请求的输入，不包含该响应和之后的工具回执，也不是模型容量声明。
若该响应已经成功 compact，旧 generation 的统计不再触发提醒；压缩后的请求重新计量。
提醒不改写固定前缀、不强制压缩，也不要求整理工作台或修改记忆。

`SessionConfiguration.context_budget_warning_tokens` 接受正整数或 None（关闭），
CLI 新建 Thread 使用 `--context-budget-warning-tokens`，0 关闭。
配置与最近提醒档位保存至 rollout，正常 resume 不重复触发同一档位；旧 Thread
缺少配置字段时采用默认阈值。提醒状态通过独立记录保存，不依赖解析 Agent 可见文本。

## 尚未实现

模型容量发现、请求前 Token 估算、预留 Token 空间、强制整理模式、超限后的历史封包与分块整理、
用户 `/compact` 命令、语义搜索、倒排全文索引和按需磁盘索引都不在本阶段范围内。
已有关键词扫描和编号寻址；查询结果仍会占用模型上下文。


主动范围压缩、resume、来源查询和嵌套压缩，再做无模型的第三次恢复校验。
