# 独立记忆基线与历史版本

## 必须成立的不变量

每次请求时，仅使用实际可见的记忆区和历史视图，就能恢复完整当前 index.md，
并与 AgentContext.read_memory 的文件内容一致。读取器统一换行语义，与现有记忆工具一致。
校验不使用隐藏原文或未展示的版本正文补缺；不一致停止请求并写入 memory_invariant_failed trace。
这保证上下文拥有完整信息，不保证模型一定遵循它；真实模型行为仍需另行验收。

## 表示与缓存

Prompt.memory 是独立的 user-role 数据片段，放在 API input 最前面，但不在逻辑 Prompt.input、
HistoryArchive、HistoryView 或历史编号内。role 是传输表示，不赋予记忆新的人类授权。
初始基线含 version/text；正常编辑保持基线及已有输入前缀不变。

后续修改仍以原生 function_call/function_call_output 进入历史。
write_memory 写入 index.md 的完整参数已存在，回执的 memory_update 用 version/source=call 引用参数。
patch 造成 index 改变时，回执附 version/text 完整版本，模型不用自己累加 patch。
错误发生前 index 已提交的部分成功，同样产生完整版本；保留 JSON error/message 字段，
增加 memory_update 字段，不能将整批错误误报为成功。
无变化、只读、仅详情文件操作不产生新 index 版本。详情仍按需读取。

当前记忆 = 高于基线的最高显式版本；没有则用基线。旧于/等于基线的记录只代表过去操作。
相同版本不同内容会报错。普通工作总结和历史查询返回的引用不是新的记忆状态。

## compact

1. 无 index 更新：只替换工作历史。
2. 最早的可连续归并更新链：推进基线到选区最后版本，不取磁盘较晚版本。
3. 选区之前仍有未归并更新：在摘要之后插入该处完整快照；原范围后面的记录顺序不变。
4. 快照可以再次 compact，多个更新/快照只保留最后所需版本，不重复累积。
5. 覆盖整个请求可见历史时：基线推进到当前版本，无需中间快照。

“整个历史”不包括触发 compact 的本次响应及工具调用，仍遵守当前批次保护和调用/回执配对。
准备阶段验证替换后的可见记忆仍准确，随后一条 history_compacted v2 同时提交历史替换与记忆投影。
写入失败是致命错误，不能当普通工具失败继续。记忆文件本身不被 compact 修改。
局部优先保留稳定前缀；整体整理允许一次基线变更带来的缓存失效，建立新的稳定窗口。
暂未实现“历史短于某个阈值自动整体重建”的启发式，也不声称测过实际缓存命中率。

## 持久化与兼容

rollout 的 memory_state 是独立运行状态记录，不是 HistoryArchive item，也无历史 ID。
它保存基线/当前完整版本；更新正文亦在可见工具证据中。待处理回执仍留在事件队列，
resume 后先消费再请求，不能提前假装模型见过它。
history_compacted v2 内的 memory_state 与替换原子提交，检查点插入原位置。
v1 仍按旧语义回放，包括旧尾部检查点，随后迁移。

旧 Thread 首次恢复时，从旧快照与可见编辑/读取重建当前内容，核对文件后做一次基线重建。
旧 <agent_memory> 消息仅从视图隐藏；稳定 ID、完整归档及 compact 来源树不变。
没有任何旧记忆证据的历史初始化一个基线。无法可靠重建或与文件不同则拒绝，不猜测。
迁移是一次性的前缀变化，不承诺旧请求字节级缓存连续；以后 resume 恢复保存基线。
不支持用旧版本程序打开包含新记录的 Thread；仍只支持正常关闭恢复，不新增任意崩溃恢复。
