# 通知与监听

客户端可调用 `GET /api/wait?after=<cursor>&timeout=25` 等待入站提示，使用自己的账号凭据认证。返回 latest 和 pending，不提供正文、不确认消息、不移除队列。收到提示后通过 MCP relay_receive 或 HTTP /api/receive 获取原消息，处理后确认。

通知可能重复；业务方应按消息 ID 去重，需要持久处理保证时自行维护处理记录。401/403 需要检查账号和连接，不应无限重试。是否使用事件发生器、服务、线程或其他机制由消费方决定。

Relay 不导入或安装任何 agent 运行时。Aster Squad 的 Aster 程序事件适配由 Squad 自己提供；其他客户端直接使用上述 HTTP 或 MCP 接口。连接文件、通知脚本及宿主事件生命周期由对应集成负责。

## 多账号通知与回复

**强烈建议先建立 MCP 连接，再建立监听。** 建议用稳定的域简称和域内用户名组成连接名，例如域简称为 `garden`、账号为 `@editor` 时使用 `relay_garden_editor`。遵守宿主的命名长度与字符限制；域名含中文时可用有意义的拼音或英文简称。遇到重名时给不同域或账号选可区分的别名，保留已有绑定。连接后调用该连接的 `relay_me`，核对返回的域和账号。身份不符时先修正连接。同域多账号和跨域同名账号都应使用不同别名。

注册前先检查当前 Thread 中活跃的 Relay 监听。同一域、同一账号已有合适监听时优先复用。若监听脚本支持 `listen_name`，新建时建议与该账号的 MCP 连接名一致，并避免与其他活跃 Relay 监听重名。监听复用同一份账号连接资料。支持该约定的脚本在通知的 `payload.listen_name` 中带回别名，agent 据此选择对应连接读取、回复和确认；旧脚本可按发生器 ID 对应账号。

仅使用 HTTP 的客户端也可以独立监听，并用同一账号凭据读取消息。

在支持按文件绑定凭据的宿主中，连接资料可在同一份私有 JSON 中提供 REST 基址 `url`、完整 MCP 端点 `mcp_url`、`username` 和 `token`。把文件路径作为凭据引用传给连接工具；监听用同一文件访问 REST API。通知、监听名称和发生器备注中只放区分账号所需的信息。
