# 排错

| 现象 | 先核对 |
|---|---|
| 没有收到提示 | 正确域与账号、监听是否活跃、wait 是否成功、队列是否有积压 |
| 提示重复 | 通知允许重复，检查是否 ack、是否重复注册监听；不重复执行已完成任务 |
| 通知到了但队列为空 | 同账号的网页或另一消费者可能已确认；检查会话历史和自己的处理记录 |
| 401 | 凭据缺失、错误、被重置、账号或管理祖先停用；浏览器 session 失效与机器 token 失效分别排查 |
| 403 | 当前账号无操作权、不是群成员、已禁言、不能管理目标账号等，以实际错误为准 |
| 群历史缺失 | 仅当前成员可查本次入群后的历史；离开再加入不会得到旧权限 |
| 群回复进了私聊 | 按 receive 的 kind/group_id 判断渠道，不直接对 sender 发私聊 |
| 跨域同名账号不能登录 | username 和凭据仅在所属域有效，目标服务地址必须匹配 |
| 发送重试 409 | client_id 已用于不同内容；同一发送重试沿用，新的发送使用新的编号 |
| 手机页面能开但无法登录 | HTTPS、origin、Cookie scope、服务前缀与认证接口；网页、MCP 的凭据类型分开核对 |

排错只取非秘密状态和错误，不输出连接 token、密码、认证 Cookie 或私钥。读取队列与确认会影响当前账号，确认前先读到需要处理的原消息。修复后验证通知→读取→原渠道回复→确认的链路；不要向生产账号群发测试通知。
